# recipegenerator

Pantry-to-Plate is a lightweight recipe suggestion app.
It takes a list of ingredients from the user and suggests meals they can make,
generated by an LLM from what they already have.

The OpenAI API key is now loaded from a local backend config file so it is not stored in browser localStorage and not exposed in frontend code.

## Features

- Add ingredients one by one
- Remove individual ingredients or clear all
- Generate recipe options from your pantry ingredients using an OpenAI model
- Apply dietary filters (vegetarian, vegan, gluten-free, dairy-free, nut-free, halal)
- Set maximum cook time and preferred difficulty
- Toggle pantry staples (salt, pepper, oil, garlic)
- Choose servings and scale ingredient quantities in generated recipes
- Show estimated nutrition stats (per serving), including calories, protein, fat, and carbs
- See match percentages and missing ingredients
- View a quick cooking method for each suggested meal
- Automatic fallback to local catalog matching if AI is unavailable

## Run Locally

1. Start the Node server from this folder:

	```bash
	npm start
1. Open [backend/config.json](backend/config.json) and set your API key:

	```json
	{
	  "port": 8787,
	  "openaiEndpoint": "https://api.openai.com/v1/chat/completions",
	  "openaiApiKey": "YOUR_REAL_OPENAI_KEY_HERE",
	  "defaultModel": "gpt-4o-mini"
	}
	```

2. Start the local Node backend from this folder:

	```bash
	node backend/server.js
	```

3. Open this URL in your browser:

	```text
	http://localhost:8787
	```

## AI Recipe Endpoint

The app can optionally call a real LLM through a server-side proxy endpoint.

1. Create a local `.env` file once:

	```bash
	cp .env.example .env
	```

2. Put your OpenAI-compatible API key in `.env`:

	```bash
	OPENAI_API_KEY=your_key_here
	```

3. Optional: override the API base URL or model in `.env`:

	```bash
	OPENAI_BASE_URL=https://api.openai.com/v1
	OPENAI_MODEL=gpt-4o-mini
	```

4. Start the app with:

	```bash
	npm start
	```

OPENAI_API_KEY is required for AI recipe generation.
If the key is missing, the AI button is disabled until you update `.env` and restart.

Note: `.env` is ignored by git so your key stays local.
4. In the app, click **Find Recipes**.

5. Optional: Set dietary filters, cook-time/difficulty preferences, pantry staples, and servings before generating.

Notes:
- The API key is stored only in [backend/config.json](backend/config.json) on your machine.
- [backend/config.json](backend/config.json) is listed in [.gitignore](.gitignore) to reduce accidental commits.
- Preference selections and selected model are stored in browser localStorage.
- The browser calls your local backend (`/api/recipes`), and the backend calls OpenAI.
- If the AI request fails, the app falls back to built-in catalog matching.

## Architecture

The app follows a **layered component architecture**:

- **Data Layer** (`js/data.js`) — Recipe catalog (70+ meals) and ingredient aliases (20+ groups)
- **State Layer** (`js/state.js`) — Ingredient state management
- **Logic Layer** (`js/matching.js`) — Local fallback matching algorithm with smart alias expansion
- **LLM Layer** (`js/llm.js`) — OpenAI API integration and AI recipe generation
- **Renderer Layer** (`js/renderer.js`) — DOM manipulation and component rendering
- **Events Layer** (`js/events.js`) — Event listener delegation
- **UI Layer** (`index.html`, `styles.css`) — HTML structure and responsive styling

See [CODE_LAYERS.md](CODE_LAYERS.md) for detailed layer-to-code mapping and [ARCHITECTURE.md](ARCHITECTURE.md) for visual diagrams.
